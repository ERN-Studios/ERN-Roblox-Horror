# Developer suit and False Sun VFX review — 24 September 2026

Read-only independent review of Claude commit `bc1192b`. The skin suite passed 31 checks and `HazmatSkinDriver` compiled, but these three acceptance gaps remain. Do not mark [developer suit](https://trello.com/c/SYUaXHKQ) or [skin VFX](https://trello.com/c/IRLeRBcN) Done, or publish this commit as the final version, until they are fixed and tested.

1. **False Sun cleanup can leave the native avatar invisible.** `StarterPlayer/StarterPlayerScripts/HazmatSkinDriver.LocalScript.lua:254` calls `state.Motes.Parent:Destroy()` with no parent guard. The server may already have removed the visual during lobby return, death or unequip. A deterministic Luau 0.737 reproduction using the exact `clearState` function at lines 250–270 returned `clearState ok=false`, `attempt to index nil with 'Destroy'`, and left an original native body part at transparency `1` rather than `0`. Make the cleanup idempotent when the attachment or its parent has already been destroyed, then test unequip, death, lobby return and rejoin.
2. **Revoked developer access must fail closed.** A saved `SignalArchitect` profile is published via `applyAttributes` and `ZyntraProfileLoaded` at `ServerScriptService/ZyntraMonetization.Script.lua:1972–2002` before `refreshPasses` calls `DevAccess.IsAllowed` at lines 2175–2187. If its one revocation `mutate` fails, there is no retry unless an unrelated pass read fails. `ServerScriptService/HazmatSkinVisuals.Script.lua:337–358` trusts the replicated skin ID with no separate access check. A former developer can therefore keep the visual for that session after failed persistence. Gate the in-memory equipped skin and its published visual immediately on current `DevAccess`, then retry durable revocation without granting nondevelopers ownership. Test an existing saved dev suit, revoke access, inject one write failure, and verify both own view and a second viewer never see the suit afterward.
3. **The standing shop preview has no False Sun motes.** The [VFX Trello card](https://trello.com/c/IRLeRBcN) explicitly requires them on the standing preview. `HazmatSkinDriver` creates motes only for an in-round `ZyntraHazmatSkinVisual`, while `ReplicatedStorage/ZyntraSkinsPage.ModuleScript.lua:135–154` clones the preview into a `WorldModel` without an emitter. Add a restrained cosmetic effect there, with the same cleanup and reduced-motion behavior, then verify it on desktop and physical touch.

No Token, wheel or Robux grant path for Signal Architect was found in this review. That is a positive source finding, not proof of forged-request, published two-client, or persistence behavior. The two cards still need real two-client, rejoin and physical mobile evidence plus a publication receipt; see [physical QA sheet](PHYSICAL_QA_2026-09-24.md).
