## Installed controller changes

The root installed the final `EntityAnimation` controller with scoped Source/editor CAS. The final teardown correction also adds one explicitly owned synchronous release call to GameManager, derived from its fresh Cinema-aware Studio baseline. This is limited to Level 1 teardown; Cinema routing and progression are preserved.

- Smooth actual horizontal velocity over 0.10 seconds and use separate 0.55/0.18 movement entry/exit thresholds. Small velocity jitter no longer repeatedly starts/stops idle and walk.
- Crossfade locomotion over 0.25 seconds, start each clip at its correctly matched playback speed, and preserve normalized stride phase between the matching v10 walk/jog cycles. Stable loops are not replayed every frame. The speed floor changes from 0.6 to 0.08 so slow movement is not accompanied by disproportionately fast feet. Original walk/run base speeds and upper cap remain.
- Keep Idle beneath the Action4 layer while a one-shot plays, avoiding an uncovered bind pose at the final fade. Action completion uses one cancellable `Ended` connection instead of spawning a new thread waiting on every action.
- Preserve and strengthen owned kill behavior: reject duplicate capture requests, reject late howl/lunge interruption while `EntityKillActive`, and wait for the full owned action fade before resuming locomotion. Original clip IDs, hit times, capture guards and action playback speed remain.
- Stop only this controller's previous tracks during startup. On entity removal, destruction, script disable or entity death, disconnect controller signals, stop and destroy every successfully loaded owned AnimationTrack (including clips that never played), and remove its generated BindableEvents/Animation instances. Destroying tracks releases the controller's loaded objects from the reused Animator. The required Walk/Run load-failure return uses the same release helper; a failed optional load immediately destroys its Animation instance. Other owners' tracks are not stopped or destroyed.

The blend, speed and phase changes use the documented [AnimationTrack playback, speed, weight and time position](https://create.roblox.com/docs/reference/engine/classes/AnimationTrack) APIs. The candidate sets TimePosition only after playback starts and only when clip lengths are available.

The final cleanup revision was requested by root after identifying that Stop changes playback but leaves the loaded track object. The [Creator Hub AnimationTrack lifecycle example](https://create.roblox.com/docs/reference/engine/classes/AnimationTrack#Ended) explicitly destroys its track after stopping and finishing its fade. Our round teardown disconnects action callbacks first, stops playback and immediately destroys only the controller's owned tracks. Fresh Play Server Source/editor parity matched the previously installed candidate; Edit was unavailable during another developer's Play session, so the revision remained offline for root's later fresh Edit comparison.
