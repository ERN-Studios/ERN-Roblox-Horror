The two loading candidates were generated from the exact Studio Source/editor exports in `.git/stutter-assets-20261009/scoped-before`, not from historical mirrors. `candidate-receipt.json` records input and candidate SHA-256 values. This generator writes only task artifacts; it never writes Roblox Studio or the authoritative mirror paths.

The lobby census reads SurfaceAppearance's runtime-readable Content map properties, deduplicates URI assets, and warms their raw images through fresh temporary Decals. Meshes remain typed MeshPart carriers: the native probes found MeshId-string fetch failures while the same MeshPart succeeded. Opaque Content values are included only when they expose a nonempty readable MeshId/TextureID. Embedded Opaque content with empty IDs is omitted from remote fetch requirements; native probes found those already embedded meshes return successfully with no asset callbacks. They must not be reported as failed downloads. A real URI texture on an embedded mesh still keeps a typed carrier and its callback requirement.

The latest scoped change is only the initial lobby preload function, reconciled against the fresh installed Studio exports in `loading-pool-before`; the receipt records that baseline. It uses at most four workers sharing a cursor, with claims before any yield. This preserves bounded parallel downloads instead of serializing them. One owner remains busy until all engine calls drain, including staggered workers after retry/skip, and stale workers cannot settle keys or update progress. Protected completion releases the owner even on an unexpected presentation error; unreported work then remains failure. Entry and background preloading are unchanged. This restores concurrency conservatively relative to the original six workers; Studio's viewport throttling prevented a controlled native timing comparison, so no measured performance improvement is claimed.

Each request records its final AssetFetchStatus. Failed or absent callbacks and thrown requests cannot become success. Retry/skip and a capped world prefetch leave the in-flight worker owning its lock until the engine request drains. Background roots are scoped to the selected round, seeded in bounded slices, and updated through DescendantAdded. Live-level covers repeat slices within one overall eight-second allowance; each repeat yields even while an older generation owns the engine request, and cannot finish before its current model is indexed. The final status also requires that the current model was indexed, so an old request draining during the settling allowance cannot turn an untouched new level into READY. A capped/incomplete/failed pass says ENTERING THE LEVEL instead of claiming LEVEL READY. End/exit resets disconnect watchers and clear queued/source references; generation checks reject late results.

Round entry keeps the existing token, character, server deadline, UI/control and observed-floor gates. It also fetches nearby visible world assets within 80 studs plus the part's bounding sphere; this includes CanQuery=false Blender ceilings that overlap queries omit. Far map assets do not become entry requirements. New nearby arrivals invalidate readiness and queue additional work; a 0.35-second quiet window precedes the existing three readiness samples. One retry is allowed. A permanently failed nearby image or mesh prevents acknowledgement and invokes the existing server deadline recovery.
