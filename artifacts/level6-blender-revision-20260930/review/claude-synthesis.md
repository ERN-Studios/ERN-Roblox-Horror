# Claude Opus 5.5 review, checked against Roblox documentation

Claude Opus 5.5 at max effort completed a tool-disabled, offline review. Its exact response is in `claude-response.md`, and the invocation evidence is in `claude-execution-manifest.json`. Claude did not inspect Studio or the Blender file directly; the prompt supplied the existing package facts. This synthesis separates useful recommendations from Roblox claims that needed verification.

## Useful design checks

- Treat the original 49 named `L6K_*` collections, anchor empties, existing seed 101 layout and placements as a baseline. Keep added assets/placements as an explicit delta. Preserve names and transforms, and use a separately derived deterministic seed for new decoration so old random placements do not shift.
- A collection-instance empty's scale does not automatically become mesh UV scale. If the Blender preview realizes scaled architecture or derives world-space UVs, retain the original instanced source and an export copy. Check actual active UVs and tangent orientation after FBX roundtrip.
- Keep carpets and walls in independent repeatable images rather than expecting one atlas cell to wrap; otherwise wrapping repeats the whole atlas and mips bleed into neighboring cells. For microfiber and DiamondPlate, generate periodic height independent of printed color and derive OpenGL normals with wraparound central differences. A staggered, beveled lozenge mask gives a raised plate without dense geometry.
- Export normal, roughness and color sidecars with file hashes, source provenance, period in studs, assigned material and target mesh path. Keep packed `.blend` copies hash-identical to the sidecars. Kitchen and service props can reuse room shells and remain clear of portal/corridor routes; temporary clearance volumes give a measurable offline check.

## Corrections and limits

- Claude marked normal orientation as unknown. Roblox explicitly requires **OpenGL tangent-space** normals and imported mesh tangents; the green channel is not inverted. [Roblox PBR guide](https://create.roblox.com/docs/art/modeling/surface-appearance), [SurfaceAppearance API](https://create.roblox.com/docs/reference/engine/classes/SurfaceAppearance).
- Claude's statement that Roblox never sees a Blender node graph is too broad. Roblox documents import of supported PBR image-node wiring through Principled BSDF and a Normal Map node. Arbitrary procedural graphs and only packing images inside `.blend` still cannot be assumed to arrive as PBR; sidecars and an importer gate are appropriate. [Blender/Maya texture settings](https://create.roblox.com/docs/art/modeling/assign-textures).
- A `SurfaceAppearance` MeshPart follows its UVs; current runtime resizing of the floor prefab would still stretch those UVs. `MaterialVariant` supplies a tileable `StudsPerTile` option for native Parts; original `Texture` supports separate U/V stud repeats. Current `Texture` also inherits PBR map fields from `Decal`, but those fields are hidden/plugin-security, so do not assume ordinary runtime assignment. [Materials](https://create.roblox.com/docs/parts/materials), [Texture](https://create.roblox.com/docs/reference/engine/classes/Texture), [Decal](https://create.roblox.com/docs/reference/engine/classes/Decal).
- Roblox prescribes UVs within 0–1 for custom meshes, while its Marketplace validation says outside values may tile or distort. Claude's >1 UV route remains an **import test**, not a proven delivery. The 0–1 world-grid face split in `normal-compatibility-contract.md` is the conservative fallback. [Texture specifications](https://create.roblox.com/docs/art/modeling/texture-specifications), [Marketplace validation](https://create.roblox.com/docs/marketplace/validation-system).
- The original Level 3 carpet and wall images are historically verified source-pack files, while the effective current Studio asset slots remain unverified. An opaque PBR ColorMap that reproduces a partly transparent Level 3 wall `Texture` over a tinted Part will need documented tint/overlay composition; direct pixel hashes may then differ from the original even when the artwork is correctly derived.
