## PBR maps

- Preserve the original Level 3 carpet and wall **color artwork**. The existing 2048 atlas's procedural carpets are different artwork, and grayscale-from-albedo height would engrave dark printed motifs into the floor. Generate a separate periodic microfiber height field from fiber-scale noise, convert it to a restrained tangent-space normal, and leave printed colors in the albedo map. Keep carpet roughness matte. Verify height and first derivatives across opposite edges before baking normals; inspect the normal itself at seams and through mip levels.
- For raised DiamondPlate, use a staggered lozenge height mask with rounded/sloped ridges and flat valleys, then bake a tangent normal. Highlight orientation should make ridges look raised from both grazing directions. Do not add thousands of diamonds as mesh geometry. Use independent restrained metalness/roughness maps appropriate to bare or painted plate; a grayscale height map alone is only an authoring intermediate.
- Roblox expects **OpenGL tangent-space** normal RGB, with the green channel pointing up in texture space; `(127,127,255)` is flat. Imported meshes need tangent information. Make normal and roughness image nodes **Non-Color** in Blender. Normal goes through a Normal Map node to Principled BSDF; albedo stays sRGB. Export RGB normal PNG, grayscale roughness PNG, and optional grayscale metalness PNG. Keep all PBR maps using the same UV orientation and tile origin. A negative scale or mirrored UV island can invert appearance and must be checked in the importer. [PBR textures](https://create.roblox.com/docs/art/modeling/surface-appearance), [SurfaceAppearance API](https://create.roblox.com/docs/reference/engine/classes/SurfaceAppearance), [texture specifications](https://create.roblox.com/docs/art/modeling/texture-specifications).
- For each textured kit or realized export mesh, sidecar metadata should name exact collection/object/material, color/normal/roughness/metalness file paths and hashes, source artwork slot, repeat width/height in studs, UV set and orientation, normal convention (`OpenGL +Y tangent`), tangent export expectation, and whether the material is for MeshPart `SurfaceAppearance` or a future native Part `MaterialVariant`/`Texture`. Pack images inside `.blend` **and** keep the separate image files. Blender procedural shader nodes or merely packed `.blend` maps are not an independent Roblox delivery. Roblox's supported Principled BSDF image wiring can import PBR through FBX/glTF, but an importer roundtrip must verify actual map assignment; otherwise assign the uploaded sidecars explicitly in Studio. [Blender/Maya texture wiring](https://create.roblox.com/docs/art/modeling/assign-textures), [environmental asset library import](https://create.roblox.com/docs/tutorials/curriculums/environmental-art/assemble-an-asset-library).

## Stud-scale repeat and importer gate

- `SurfaceAppearance` applies PBR to a MeshPart's UVs; `MaterialVariant` is Roblox's reusable tileable PBR material with `StudsPerTile`; a native Part `Texture` uses separate `StudsPerTileU/V` and keeps repeat size when the part resizes. The systems are not interchangeable. [Materials](https://create.roblox.com/docs/parts/materials), [MaterialVariant](https://create.roblox.com/docs/reference/engine/classes/MaterialVariant), [Texture](https://create.roblox.com/docs/reference/engine/classes/Texture).
- The native `Texture` route preserves the original Level 3 image and repeat. Current API documentation shows `Texture` inherits the newer `Decal.NormalMap`/`RoughnessMap`/`MetalnessMap` properties, but marks those maps **Hidden / Plugin Security**. Do not assume normal maps can be installed by ordinary runtime scripts or that the old `Texture.Texture` plus a new inherited map has been verified. A future Studio import/capability test could confirm a tiled PBR `Texture` setup; documented alternatives are a paired `MaterialVariant` ColorMap/NormalMap (with Level 3 tint/overlay composition reproduced in the color map) or MeshPart `SurfaceAppearance` with suitable UVs. [Texture API](https://create.roblox.com/docs/reference/engine/classes/Texture), [Decal API](https://create.roblox.com/docs/reference/engine/classes/Decal).
- The proposed realized architecture with active UV `world position / repeatStuds` is right for Blender's physical preview, but it yields UVs outside 0–1 on large rooms. Roblox's [texture specification](https://create.roblox.com/docs/art/modeling/texture-specifications) prescribes UV coordinates inside 0–1. Its [Marketplace validation](https://create.roblox.com/docs/marketplace/validation-system) says outside coordinates can tile, stretch or map incorrectly and are a quality warning for those assets. No official general-import promise for >1 UV wrapping was found. Gate that export with a small FBX reimport and Studio visual check before calling it Roblox-ready. A conservative mesh fallback is to split architecture faces on a world-aligned tile grid and restart UV within 0–1 on each face, including fractional UVs at edge cells; this keeps physical scale without relying on >1 UVs. A future native Part route can instead reuse the effective Level 3 `Texture` slots and stud repeats.
- For the 0–1 fallback, split a floor face at every world-space `n × repeatStuds` line and set each new face's UV to `(worldXY − tileOrigin) / repeatStuds`; map wall faces from their world horizontal coordinate and Z in the same way. The tile origin must be shared across adjacent rooms and corridors. Partial edge faces simply use a fraction of the tile. Keep tangent orientation consistent and avoid mirrored wall UVs, or a normal may appear recessed on one wall orientation.
- Roblox's current texture specification page states a 4K general upload allowance but also says 1024×1024 in its UV section; do not treat that internal discrepancy as a proven per-map cap. Deliver practical 1024 or smaller sidecars where detail survives, retain source resolution, and verify actual importer acceptance/quality on the target mesh. Its rendering can choose lower quality mip levels by device. [Texture specifications](https://create.roblox.com/docs/art/modeling/texture-specifications).
