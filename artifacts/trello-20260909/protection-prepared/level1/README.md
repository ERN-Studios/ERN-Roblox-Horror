# Level 1 protection integration — artifact proposal

Prepared for the approved 5-token / 5-second item, 10 September 2026. This directory contains **five proposed source copies, immutable baselines and an isolated diff**. No runtime file, Studio instance, live DataStore, purchase, profile, Shop UI or published place was changed. Protection is not installed and the whole feature is not complete.

## Scope

| Proposed file | Behavior |
|---|---|
| EntityAI | A server-private `targetable` predicate covers footstep intake, vision, held ALERT/TRACK targets and lunge eligibility. New footsteps carry the optional source-player identity introduced in the Level 2 NoiseRegistry proposal. Activation clears only that player's sight/ALERT/chase/search/noise-route ownership, chase marker, lunge and pending/active yell impulse. A synchronous lunge Heartbeat check runs before the airborne branch; a brain check also clears protected memory before ALERT can return early. Teammate targets, relay/world sounds, neutral objective wandering, lunge cooldown and authored movement values remain. |
| EntityKill | Each touch reserves one private capture record with a generation/serial ID before spawning work. Every delayed capture/pull/pin/impact step checks that record, its round epoch and exact player/character/Humanoid/root. The final private protection guard precedes both death feedback and Health=0. An activation cancels only the matching capture's tweens and lifecycle listeners, restores the living player's pre-grab pose and original movement/rotation/platform/anchor settings, restores the entity, stops its matching animation and tells that client to cancel. Round/character/leave/escape cleanup invalidates old continuations. A completed fatal hit retains its ordinary death fade rather than being changed into a cancellation. |
| JumpscareUI | Capture, death and cancellation messages match ID plus character. Matching cancellation releases controls, overlay, render binding and the captured camera settings. Both the yielding PlayerModule lookup and every fade wait have owner checks, preventing old work from disabling controls or deleting a new character's UI. Normal pit/other death fade and the disabled legacy image block remain. |
| EntityAnimation | A deferred old PlayKill checks current capture ID/state before playing; a matching CancelKill stops that capture. A small private action serial also prevents an old Ended waiter on the reused Kill track from clearing the newer action's ownership. Existing clip IDs, locomotion setup and animation rates remain. This fifth file is required because stopping an already playing track alone cannot cancel a still-queued PlayKill event. |
| MazeGenerator | Protected pit contacts are remembered by player, character, Humanoid, current bottom part and local round epoch. On the first Heartbeat at/after private expiry, damage occurs only if the same live participant still intersects that bottom's bounds. Leaving, escape, respawn, a removed bottom or round change discards the old contact. Ordinary pit death and the entity's existing rescue teleport are retained. No player rescue teleport or healing is added to the pit. |

The pit uses a bounded Heartbeat pass over **only recorded protected contacts**. While protection is active it performs eligibility/private-state checks, not spatial scans. At expiry it queries the original bottom with character-only overlap and 0.3 studs of vertical contact tolerance at either face. It neither trusts the published display deadline nor kills someone merely for remaining somewhere in the shaft. Engine overlap/contact behavior still needs native acceptance.

Capture cancellation restores the **pre-grab CFrame**, rather than simply unrolling the last floor-pin pose: unrolling that low pose would leave an upright root partly inside the floor. This restoration applies only to the same living captured character, without changing Health. Delayed tweens are cancelled before restoration and fenced again after their waits. A private script-generation GUID plus serial prevents an old client cancel/death from matching a later script generation's capture.

Yell work is keyed per player. This preserves simultaneous existing impulses toward different players, while cancelling one protected player's pending and already-created BodyVelocity. A launched lunge stores the actual player/character used at launch, including a target change during windup. Cancelled work cannot resume when protection expires.

## Files and integration

`before/` contains exact baseline bytes; `baseline-sha256.json` identifies them. `proposed/` contains complete proposed files at their intended paths; `level1-protection.diff` is the scoped patch. `prepare.py` regenerates from saved baselines, and the small handler/replacement artifacts are its inputs. **Merge the diff against the current runtime sources before later installation; do not overwrite newer unrelated changes with these copies.**

Install the already reviewed `../PlayerProtection.ModuleScript.lua` server singleton and the `../level2/` NoiseRegistry proposal together with the eventual consumers. No fallback silently disables protection when the required service is missing. Existing Level 1 two-argument world-noise calls are untouched; only actual player footsteps acquire a source argument. This proposal does not change the Level 2 preparation, Level 3, persisted item transactions, purchase/UI logic or any rollout flag.
