The decision to press now depends on the actual pointer arriving within2 pixels of the freshly measured button center plus the native-calibrated GuiInset. `MouseBehavior` is logged only; it is neither a condition nor written by the fixture. This matches the concrete issue: actual RoundUI owns cursor policy during rendering and its result buttons are Modal, so an intermediate enum value is not reliable evidence that the pointer cannot reach the button.

The at-most.75-second Heartbeat loop rechecks cancellation, current player/GUI/window, button visibility/activity/interactivity, available input, center and inset after each yield. Before mouse-down, the current viewport, hit target and actual pointer are checked again; there is no yield between those final checks and the press. A stop cannot cause a later new press, and the hold continuation sends mouse-up only if the fixture still owns an outstanding press. Stop disconnects both the result and actual-input listeners, cancels its timer and records any release error.
