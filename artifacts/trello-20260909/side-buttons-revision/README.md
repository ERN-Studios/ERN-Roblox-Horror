# Small left-side Shop controls — prepared revision

This implements the user's revised layout: Shop above Upgrades at the left safe edge, with a geometry slot for a copy of MUTE DISPATCH underneath. It supersedes the earlier larger, horizontal square layout. Store keeps the existing image assets, captions, palette, click handlers and page behavior. RoundUI owns the actual mute button in the separate `side-mute-revision` proposal.

The sole Store baseline is `b031c3ab5b27edb484b5a62c40fcb380434df1c664d6cb51811e27c7b688a3cb`; the prepared Store is `5638699125280c0980128946efb1c20018da219c3c263d9e9c21bc402843ee6b`. Exact paths and hashes are in `manifest.json`. `before/` is immutable. `prepare.py` regenerates artifacts from that captured baseline and verifies an exact inverse; it does not install production code. Installation and native acceptance belong to root. The separate root-owned `apply_reviewed_revision.py` checks both Store and RoundUI baselines before either write.

The rail uses 64 px desktop buttons or 56 px touch buttons, with 52 px only when the actual available geometry requires the smaller option. It begins at Safe.Left + 8 / Safe.Top + 8. Shop is first, Upgrades second, and `ZyntraStore.ZyntraSideMuteSlot` is 44 px high, eight pixels below Upgrades. The slot is transparent and inactive; it remains eligible during Dispatch briefing, yields to full modals/queue/gameplay, and follows the measured briefing rectangle. Pauli's RoundUI copy follows this slot's size and visibility and shares the existing private mute state and handler.

Each image is fitted completely inside a frame inset three pixels from the outer button, above a separate 16 px caption. This prevents the Shop bitmap from painting over the rounded border. Captions are explicitly unscaled: 12 px at 64, 11 px at 56, and 10 px at 52. Native 12 px measurements from the preceding version support the 64 px width; the 10/11 px estimates require actual native TextFits checks.

On the captured iPhone 13 geometry (749 x 310 safe area), the normal 56 px layout is Shop (8,8), Upgrades (8,70), and mute slot (8,134), ending at y178. The actual resting thumbstick glyph begins at y217, leaving 39 px. The broader invisible DynamicThumbstick activation region covers most of the left side and cannot accommodate the requested three-control rail. This revision deliberately permits that region to overlap active GUI buttons, while protecting the measured visible glyph and right-side controls. Native taps must establish that these buttons consume input without starting movement. This is an explicit layout tradeoff, not a claim that the entire joystick activation region is clear. Desktop ignores cached touch zones. A genuinely insufficient space case returns unavailable rather than overlapping visible controls or moving the rail to the right.

`test_proposal.py` passed 147 checks using the actual builders, layout, visibility and small binding block in a controlled host, including the captured phone geometry, desktop phantom zone, portrait, 52 px fallback, briefing resize, round/modal recovery, captions and inset bounds. Both targeted negative controls fail as expected (right-edge placement and missing inset). Both whole sources compile, and the prepared transform inverts byte-for-byte to its baseline. These checks do not substitute for native font rendering or touch input.

Native acceptance is bounded to the revised layout: inspect desktop/phone caption TextFits and clear borders, confirm Shop then Upgrades order and the mute copy below them, exercise both opener routes, and verify original/copy mute state synchronization during briefing. On actual touch, tap each control while recording the real stick's movement state; verify return from the Store restores the left rail. Existing native files in this directory are root-owned evidence and are preserved independently of preparation. No publication is asserted by this document.
