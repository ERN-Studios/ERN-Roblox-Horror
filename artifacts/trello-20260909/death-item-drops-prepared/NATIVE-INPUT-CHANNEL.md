# Temporary actual-input channel

Prepared artifact only. No Studio execution or production source changes by the author. This setup performs controlled real-player Approach positioning, camera aim and public virtual **E** input. It does not call Triggered, grant inventory, alter health or mark an objective complete. Root remains responsible for execution and evidence.

1. In the actual two-client **server Command Bar**, install the reviewed `native-commandbar.server.luau` if `_G.TrelloDeathDrops` is absent. Run `native-input-channel.server.luau`. Copy the returned `RunId`.
2. Replace only `RUN_ID = "REPLACE_WITH_SERVER_RUN_ID"` in `native-input-channel.client.luau`. Run that same substituted file in actual client **-1** and actual client **-2**. The code checks each real LocalPlayer, exact experience, random remote name and RunId. No synthetic second player is created.
3. On the actual server, inspect `_G.TrelloDeathDropChannel.Read().Clients` for both acknowledgements. Obtain current keys from `_G.TrelloDeathDrops.Targets()`; keys identify exact prompt instances and must be obtained again after replacing the staging helper.
4. Call `_G.TrelloDeathDropChannel.Input(-1, observedKey)` (alias `Use`). It calls the reviewed Approach, waits .35s for replication, sends the exact observed path + position to that one client, then waits up to 10s for its matching sequence report. Calls must be sequential. The client repeats actual alive/character/world/token/proximity/E checks, aims the existing camera and settles .3s, holds E with the reviewed lifecycle cleanup, and reads actual inventory after .7s.
5. Require the returned `Result.ActualTriggered == 1`, `Result.Released == true`, `Result.SameRoundAtReadback == true`, `ServerSameContext == true` and the expected actual carry text/CD attributes. Cross-check actual server drop identities/counts and the existing `native-readonly.server.luau` snapshot. A transport acknowledgement, successful SendKey call or client report alone is **not** server-side inventory proof.
6. For actual death, keep the other real player alive and call the existing reviewed `_G.TrelloDeathDrops.Kill(-1)` separately, as the controlled ground-death setup. The client prints `[DEATH_DROP_DEAD_CLIENT]` .8s after its **actual captured Humanoid.Died** with current carry text, CD count/mask, health and SameCharacter. This one-shot subscription covers the character present at harness arm; rearm after a new character if another death observation is needed.
7. After real drop creation, use a fresh exact drop key with `Input(-2, dropKey)`. Require the actual recovered count, original drop disappearance and unchanged objective award counts. Root's separate sequence may pause after Approach for screenshots before this input.

Every command is guarded by run, real recipient, sequence, one outstanding request, captured character/world/round token and an eight-second input deadline that remains checked through camera settle and hold. Timeout closes this channel rather than accepting an unknown result. The server's `Commands` report and `[DEATH_DROP_CHANNEL_RESULT]` output are serializable; client gameplay events remain the normal existing prompt events. Actual window/input delivery remains a native observation, not an assumed property of this adapter.

Stop using `_G.TrelloDeathDropChannel.Stop("finished")` on the server. Its own client commands release only the key owned by this fixture; its own random RemoteEvent is destroyed after one second. Both sides also expire after 600s. No existing gameplay remote or production instance is destroyed. The staging helper has its own independent lifetime; rearm it normally if expired. No sequence automatically kills a player.
