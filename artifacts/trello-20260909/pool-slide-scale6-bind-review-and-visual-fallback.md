## Bind reconstruction review

For an asset vertex `v`, mesh-local bind frame `B_i`, uniform import/model scale `s`, actual animated world bone frame `A_i(t)` and normalized weight `w_i`, the probe calculates:

`v_world(t) = sum_i w_i * A_i(t):PointToWorldSpace(B_i:PointToObjectSpace(v) * s)`.

This is the normal linear-blend construction: move a bind vertex into each bone's bind coordinates, apply the observed uniform scale, transform by the actual engine pose, then blend. It does not multiply the global model scale twice, does not rely on guessed mesh origins and does not modify Bone.Transform. Existing imported static RootPart→MeshPart Motor6D closure is checked by the real RigAdapter before sampling. Bone names must be unique in the rig and match every mesh bind bone; virtual bones and unweighted/invalid vertices are rejected.

`s` comes from ratios between matching asset bind-bone distances and actual instance rest-bone distances. Merely a plausible ratio would be insufficient. The probe checks that every bone's rest transform maps the mesh coordinate basis into the same world frame. The review found that a tolerance measured only at the origin/unit axes could amplify at vertices with large authoring coordinates. The revised probe additionally checks every vertex's active influences against the same rest mapping, rejecting disagreement above 0.02 studs. Mapped rest vertices must also lie inside the current MeshPart box within 0.05 studs. The asset reads were rejected before any of this mapping executed, so **none of these validations has passed natively yet**.

Remaining limits: this is a calculated linear-blend skin, not renderer vertex readback. It assumes the imported skeleton has not introduced an unrepresented deformation system; extra wrap/FACS/morph effects would need separate handling. Rest-envelope containment is a sanity check, not a comparison against rendered vertex coordinates. Validate visible landmarks and extreme poses before trusting final dimensions. A 60 Hz phase sweep is finite; clip blends/turns still need testing. Frame time measured while this scanner runs is meaningless as NPC performance evidence.

The official [EditableMesh reference](https://create.roblox.com/docs/reference/engine/classes/EditableMesh) defines mesh-local bind frames and corresponding skin weights; [Bone](https://create.roblox.com/docs/reference/engine/classes/Bone) exposes actual transformed world frames. Roblox also describes [linear blend skinning](https://about.roblox.com/newsroom/2023/12/inside-tech-solving-avatar-facial-expressions) in its animation technology. These support the model, but do not establish that this particular imported rig passes the reconstruction checks.

## Fallback: inspect the actual rendered skin against an opaque measuring volume

This avoids uncertain perspective-to-stud estimates and does not require mesh-data access. It is a **finite renderer containment test**, followed by real corridor QA; it must be reported as such. Use an isolated clone during normal Play and restore/remove all measuring objects afterward.

1. Give only the measuring clone a distinct bright material/color and `DoubleSided=true`. Remove/neutralize only its copied SurfaceAppearance/texture if needed to distinguish a pixel of skin from the gauge. This affects appearance, not the skeleton or mesh coordinates. Preserve a second normal-looking view for judging the real visual result. The real template/round entity stays unchanged.
2. Create an anchored opaque rectangular measuring block around the candidate allowed volume, collision/touch/query disabled. Set its floor-relative bottom/top to the proposed allowed skin heights. Because the block is opaque, skin entirely inside it is hidden from every exterior camera; actual protruding skin is visible outside a face. Use six unobstructed views looking squarely toward ±X, ±Y and ±Z, plus short oblique sweeps to catch a thin edge. Frame the entire possible extent, not just the box. Do not rely on an AlwaysOnTop Highlight, which defeats occlusion.
3. Test the gauge before interpreting a hidden model as a pass. Deliberately shrink one dimension through an already visible limb/head and verify the known protrusion renders on the expected face, then restore the candidate volume. Repeat for the floor and a side. This negative control checks material visibility, backface behavior, depth occlusion and possible whole-mesh culling. If the deliberately protruding skin disappears too, the gauge is inconclusive and cannot be used to approve fit.
4. Play all four actual clips through full cycles. Include walk↔run, idle↔walk, attack entry/recovery and yaw turns. Use phase seeks for any suspicious/extreme pose, with real engine settling. Record six-face coverage rather than a single attractive angle. Inspect at full viewport resolution and capture the limiting poses with the block dimensions/pivot/floor in the accompanying JSON. An inset test block can add a visible reserve instead of judging pixel-perfect tangency.
5. **Respect the circular agent radius.** A box with half-width=R and half-depth=R can contain vertices at radius `sqrt(2)*R` and therefore does not establish fit for AgentRadiusR. For a rectangular gauge with half extents `hx,hz`, require `sqrt(hx^2+hz^2) + 0.1 <= final AgentRadius`. Choose measured asymmetric half extents to avoid unnecessary width. The gauge height and absolute top above the navigator foot plane must both fit final AgentHeight with at least0.3 clearance. AgentRadius≤12/AgentHeight≤24 remain required. A visually narrow box whose corners meet this formula gives a conservative radial container at every yaw, unlike a centreline ceiling check.
6. Remove the measuring block and inspect actual feet against a floor/ruler at the navigator's real `GroundOffset + 0.08` placement. Check side and underside for penetration and gaps. Move the clone along a straight stage at 10,20,32 with the actual adapter rates; use visible floor markings to assess planted-foot slip. The bone-derived rate candidates guide the test but cannot certify soles. Verify any adjusted rate through actual locomotion, not just a paused pose.
7. Repeat the accepted body through the new physical arches, ribs, mouths, pressure doors, both axes and off-centre turns under the real Navigator. Check attack extension near walls/roof and below-foot motion separately. A gauge does not validate world collision tessellation or navigation.
