# Six synthetic choice rows through the actual Continue UI

Artifact only. Root executes these two short scripts; no production edits, installed helper, new remote, attribute writes, player movement, objective completion, server roster or transport mutations. The server script sends the existing `RoundStatus` remote to one explicitly selected real client. It invokes the actual `win`, `postwinchoices` and `lobby` client branches. Win sounds and the normal client cursor/result state therefore run too; this is not a read-only fixture. The separate client probe is read-only.

Install the reviewed **revised** Continue UI first, retaining the root's camera fix. This package does not install either change. Use a fresh quiet Studio lobby, outside the real two-player result test. `RoundActive ~= true`, target `InRound ~= true`, and a live humanoid are required. With multiple clients, set `TARGET_USER_ID` explicitly (local test users can be `-1` or `-2`) and activate that exact native client window for screenshots/input. The six `TEST_` names are synthetic; only the recipient is a real Player. No synthetic names are added to the server roster.

## Short sequence

Edit only `ACTION`/`TARGET_USER_ID` in the supplied server command, or substitute those two local literals in the execution payload. Run `client-readonly.luau` in the chosen Play client and save each return as JSON beside the corresponding actual screenshot. No `_G`, module cache, listener or background loop is needed.

1. **`begin`** sends `win(222,6,6,serverNow+15,2,-61001)`. After at least 0.7 seconds (the existing entrance/divider tween), save a baseline client snapshot. There must be no visible party rows. The original title, divider, stats, hint and two buttons are present.
2. **`rows`** sends revision 1 for serial `-61001`: Aurora/CONTINUE, Birch/LOBBY, Copper/CONTINUE, Delta/LOBBY, `TEST_LongName_123456`/CONTINUE, Foxtrot/LOBBY. All displayed usernames include `TEST_`. Wait a render frame and save a snapshot and screenshot. Compare every original composition Position/Size/Anchor/Rect with step 1 at the **same viewport**. They must be unchanged. The hint text naturally counts down; no need to require identical text. Check each visible row's native `TextFits`, both lines and no overlap with the original title/divider.
3. **`stale`** sends the same serial/revision 1 with `TEST_STALE_MUST_HIDE`, then wrong serial `-61002`/revision 99. The six original rows must remain unchanged; the stale name must never appear. This is client packet fencing, not a real multiplayer identity test.
4. With the cursor on the row strip, physically wheel/drag to the bottom on a scrolling viewport. Save top and bottom client readbacks. Across those views each of the six actual row labels must be fully reachable. The bottom readback should approach `MaxScrollY`, with the final row(s) `FullyInWindow=true`. A nonzero CanvasSize alone is not evidence of working native input. If using a controller, exercise actual scroll focus separately; a programmatically assigned CanvasPosition is only geometry evidence.
5. **`clear`** sends revision 2 with an empty roster: the strip becomes hidden, so all rows are effectively hidden (their own Visible flags can remain true). **`restore`** sends revision 3 with all six again. This tests rollback rendering without touching the original actions. The initial 15-second deadline is deliberately not extended by any roster packet. After it expires, disabled buttons/`ENTERING LEVEL 2` are expected in this display fixture: no real GameManager session was created to route the player.
6. While scrolled down, **`new`** sends a new `win` with serial `-61002` and its own normal 15-second deadline. Existing `completion.start` must clear the old rows and reset CanvasPosition to zero. **`old`** then sends the old serial `-61001` with revision 999; it must not restore any rows. Save the actual hidden-row/zero-scroll readback.
7. **`reset`** sends actual `lobby`, then **`old`** again. Ending and rows stay hidden and old text stored inside invisible labels is not visible history. Save the readback. Stop Play/End Session after the display checks to discard all client presentation state; do not publish during Play.

## Three views, no extra matrix

- Actual desktop viewport first. Most widths yield two columns and need no scroll.
- Actual **568×270** viewport, or the closest native Device Simulator/resize that the root can obtain; record the returned dimensions and native safe inset rather than claiming the requested size. Two columns can overflow the available top strip.
- Actual **320×568** portrait viewport, or closest native equivalent. One column needs scrolling. The 20-character TEST username checks the supported Roblox username length while keeping synthetic identity obvious.

After each viewport change, rerun `begin` and `rows` and capture the actual settled UI. Prefer native viewport resize/Device Simulator. Existing `ForceTouchUI` may be used by root to exercise the touch layout when Studio still reports a keyboard, with original value saved/restored. If `UIRegressionViewport` is used instead, label the images **synthetic layout**; it does not resize the native full-frame GUI by itself and cannot establish physical phone fit. Neither helper changes these attributes. The probe records both to prevent a mislabeled pass.

The original composition has not been moved by this feature; comparison is before/after rows within the same current UI, including any separately accepted camera patch. Existing offline source subtraction already proves the old geometry and 15-second flow unchanged. This small fixture covers native text, clipping, row scrolling and reset. Root's separate **two actual clients** must still demonstrate real usernames, accepted choices and normal **15-second auto-continue**. A fake `win` event does not prove objective completion, teleport success or that real players agreed to anything.
