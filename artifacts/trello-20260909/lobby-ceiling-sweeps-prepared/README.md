# Five lobby ceiling sweeps — prepared only

Trello https://trello.com/c/lXtjnc8N requests five different ceiling-light sweep patterns chosen at random. Dedicated reads contained no further description, comments or checklist. This is an automatic ambient effect; the existing manually triggered Party button keeps its separate behaviour.

One new `StarterPlayer/StarterPlayerScripts/LobbyCeilingSweeps.LocalScript.lua` controls the existing28 tagged lamps under `Workspace.ServerLobby.TunnelLighting`. The actual Builder places two rows at X±9 with14 positions from Z−128 through119. No lamp, geometry, asset, remote or server script is added or changed. A client script lets each player's existing ReduceFlashing preference suppress the new animation.

The five spatial patterns are near→far, far→near, centre→ends, ends→centre, and opposite directions in the two rows. Each is one broad six-second cosine highlight, followed by a randomly chosen9–16 second rest. Selection is random without immediately repeating the last pattern. The lamps retain their original cyan base; the highlight blends up to65% toward pale cyan and increases their original brightness by at most45%. It never darkens the road, disables lamps or changes material/range/shadows. There is no rapid on/off sequence or added sound.

The controller waits for the loaded `ReduceFlashing=false` attribute and runs only outside rounds/reserved servers. It cancels immediately on preference/round/Party changes, and detects a replaced lobby or streamed-out fixture on its20Hz tick. New fixtures join the next sweep. The server's existing `PartyModeActive` attribute has priority. Before writing any lamp, the controller checks all attached targets against the last native readback, or their captured baseline before the first write. Any changed property cancels the whole sweep and starts the normal quiet interval. Restoration changes only properties still equal to the controller's own last native readback, preserving Party values that arrived before its flag. It remains paused through the server's existing0.9-second restoration before that flag clears. Script destruction restores its own changes and disconnects subscriptions.
