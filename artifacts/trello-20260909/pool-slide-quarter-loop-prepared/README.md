# Quarter-loop Walk copy — proposed asset preparation

This is an alternative to adding phase-seek or loading state to the nonyielding RigAdapter. It changes the Walk clip's time origin globally: **new Walk time 0 equals old corrected Walk time 0.25833332538604736**, one quarter of its unchanged 1.0333333015441895-second loop. No production source, IDs, assets, models or tracks are changed or published by this builder.

Root can load `build-quarter-walk.luau` as a function and call it with the existing reviewed `ServerStorage.TEMP_PoolSlideContactCopiesV2_20260910` Folder. It returns an **unparented** Folder named `TEMP_PoolSlideQuarterWalk_20260910` and a report. Root may parent that disposable Folder for native preview. Idle, Run and Attack are exact clones of V2; the original V2 Folder is preserved. Attack retains its one Contact marker at 0.5 seconds.

The actual Walk has 63 keys after contact correction. Its 21 pose channels all have Linear easing, constant per-channel weights, and matching explicit time-zero and terminal values. The original authored non-Root endpoints are byte-identical; V1 intentionally closes the Root correction as well. The builder verifies these concrete conditions and refuses changed/nonlinear input. It does not attempt a general easing-curve conversion.

Each existing nonterminal key is cloned at `(oldTime - cut) mod length`, preserving its poses, easing, weights, names and markers. The old terminal key is an equivalent copy of old zero and has no marker; removing it avoids two different keys at the same shifted time. The old wrap is now at **0.7749999761581421** seconds. Markers on retained keys move with their original keys. A terminal marker is explicitly refused because dropping or coalescing it would require a separate policy decision.

The quarter cut lies between existing keys. For every pose channel, the builder finds its own bracketing keys, then inserts that interpolated pose in full hierarchy at new times 0 and length. [CFrame:Lerp](https://create.roblox.com/docs/reference/engine/datatypes/CFrame/ToOrientation) uses linear translation and shortest-arc rotation Slerp; splitting the existing Linear interval at this value preserves its two subintervals. [PoseBase easing](https://create.roblox.com/docs/reference/engine/classes/PoseBase) controls interpolation to the next pose. New boundary keys contain no markers. The result has 64 keys and the same duration, loop flag and priority. Existing child-channel key values are preserved with shifted timestamps; their phase is deliberately different.

`test_quarter_walk.py` executes the actual V1, V2 and quarter builders on the saved authored clip data using an instance/math host. It checks **42,667 conditions**, including 20,915 dense samples across 21 channels, shifted original-key identity, matching new endpoints, unchanged other clips/Attack marker, valid shifted marker behavior, and refusal of wrong source, nonlooping, nonlinear, mismatched endpoint and terminal-marker input. Both external source artifacts and original clip data remain unchanged. The full builder compiles.

The independent Python evaluation uses SciPy Slerp. Maximum positional difference from the phase-shifted V2 curve is 2.50e-16; maximum rotational difference is 8.08e-7 radians. Original float32 matrices are slightly non-orthogonal, so the test's two independent quaternion/orthogonalization implementations do not give bit-identical rotations. These are structural and mathematical checks, not native Animator or rendered-mesh measurements.

Before selecting this mechanism for release, root must compare native Bone.Transform poses against V2 at matching phases, especially new 0/length, the inserted cut brackets and the old wrap. Then validate all relevant transitions into and out of Walk with the cached full mesh, inspect ordinary locomotion/loop behavior, and check actual controller operation. The successful four-phase frozen incoming-quarter result alone is insufficient. No runtime-seek implementation or cold-track loading assumption is introduced here.
