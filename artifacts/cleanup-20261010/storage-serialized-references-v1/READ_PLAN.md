# S04 bounded raw serialized reference capture — proposal

The five retired forests remain present. This proposal creates no Instances,
stages/requires no Source, deserializes nothing and writes no original property.
Root alone may execute it after its receiver/config/source are reviewed and
pinned. The current file is a proposal, not a native-completed port.

Append the complete unchanged S04 common prefix, `PORT_CONFIG` from a **fresh**
Root capture and `native-read-proposal.luau`. Use a new capture ID/owned namespace
and a reviewed loopback receiver URL. Keep its native request distinct from the
controlled absence trial; never overlap leases or retry unknown completion.

The config pins all 213 current native Source/editor/class/property baselines,
52 current ServerStorage roots and the exact five-forest archive SHA
`e808f055403bd331b76e0831955b192abc8b4a914865c3936aa9b2d23ed2a8d7` /
8050869 bytes. A changed baseline refuses the read port. The fresh ledger is
purpose-bound current identity metadata, not the lost historical ledger.

The operation verifies exactly 109 current WeldConstraints, their Archivable,
identity, parent, metadata/children and actual reflected BasePart-valued,
serialized Part0Internal/Part1Internal specs. It verifies StarterPlayer identity
and actual Instance-valued serialized PlaceAvatarRules spec. It records actual
readability counts/errors without converting unreadable fields to null.

One joint native serializer input contains all five old forests (all 1617 target
nodes), StarterPlayer and each of the 109 WeldConstraints. Constraints already
under StarterPlayer are covered there and are not duplicated as root inputs.
The complete input forest must be Archivable and nonoverlapping. All current
109 witness identities must remain covered; new/disappeared witnesses refuse.
The raw payload is bounded to 32 MiB and serialized twice byte-exact. The complete
StarterPlayer tree and all witnesses have owned change/child/attribute watchers.
Existing common guards preserve all five trees and all 213 Sources/editor records
before/after serializer and transfer yields.

Only the raw engine buffer is transferred in 500000-byte parts, with exact byte
length/SHA and a capture-ID header. A saved payload is precompletion evidence.
The receiver must bind to loopback only, accept only this capture ID and
`references` part kind, reject duplicates/reordering/oversized bodies, exclusively
create a new owned directory, preserve partial/failed raw files, verify the
final length/SHA, and accept final completion separately. It must not claim
reference absence from a transfer. This proposal intentionally does not supply
or invoke an unreviewed receiver.

Every owned connection is independently disconnected even on exception. Failed
disconnects remain reachable in the owned ledger; failed/foreign leases are
preserved. Final and post-cleanup guards must pass independently. There is no
rollback step because no original mutation exists. Local transport close is not
native cancellation. A complete API envelope and known completion must be saved;
unknown outcome stops follow-up native calls until Root resolves it.

Offline acceptance is a separate narrow next port:

1. Parse the **raw** native binary INST/PRNT/PROP referents and retain every unknown
   property/chunk. Do not begin with normalized Lune reserialization. Validate
   all 1617 old target nodes, exactly 109 WeldConstraints and one StarterPlayer,
   root coverage/classes, duplicate referents and unresolved references.
2. For the actual serializer schema, establish the wire property names and types
   corresponding to Part0Internal/Part1Internal and PlaceAvatarRules. A public
   Part0/Part1 alias alone is insufficient. Require the relevant raw Ref columns
   to exist and be decoded completely, or preserve pending. Omitted properties
   and dropped unknown fields are never treated as null.
3. Map every decoded endpoint referent in the same joint DOM. An endpoint outside
   the target forest may be serialized as external/null; this proves only that
   the serialized slot does not refer to one of the included old target nodes.
   An endpoint to any old root or descendant blocks removal. Public native
   endpoint values provide a consistency crosscheck, not hidden-slot proof.
4. Retain raw/reflection/readability/unknown-property receipts and verify raw
   inputs unchanged. Optional XML/Lune views are secondary; omission or failed
   canonical equality cannot certify this gate. Property semantics not proved
   by raw/schema evidence remain pending.

Actual existing evidence demonstrates StarterPlayer serialization is supported:
the earlier diagnostic joint native capture was decoded into 576 items / 105
Refs, with **explicit serialized PlaceAvatarRules null** in
`diagnostic-reference-offline-verification-v2.json`. That is a different target
set/capture epoch and does not prove current S04 reference absence. The old
verifier's `absent canonical property (default null)` branch must not be reused
for this new gate.

This pack does not settle compatible **nonserialized** holders:
GuiService.CoreEffectFolder/CoreGuiFolder (Folder), Selection.ActiveInstance and
StudioService.HoverInstance (Instance), Player.PendingRequestedTool (Instance),
and BasePart.PhysicsRepRootPart (BasePart). A failed native read, a field's name,
nonserialized status or current Selection:Get alone does not prove these null.
They remain explicit pending boundaries. Actual reflected target types can
exclude GuiObject/Plugin/StyleSheet/LodDataEntity/SlimAnimationDataEntity slots
because none of the five target forests contains those classes; the actual
target-class census and reflection type evidence must be pinned for that claim.

Even capture and raw serialized-reference PASS do not authorize deletion. A final
removal gate still needs fresh all-readable-reference/selection checks, accounted
compatible nonserialized boundaries, exact original/Source CAS and a fresh joint
property-reference guard immediately before the actual removal. No gameplay,
multiplayer, streaming, performance or deletion certification is produced here.
