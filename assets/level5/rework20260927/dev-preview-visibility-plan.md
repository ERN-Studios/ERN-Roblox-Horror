# Showing unfinished Level 5 references to developers

**Implementation update, 2026-09-27:** Interim approach B is now installed in the live Studio place and was Play-tested with a whitelisted developer. The gallery and camera status UI are WIP; the ten views are not 1:1 or integrated into the playable route. See [the live Studio gallery QA record](studio-gallery-qa-2026-09-27.md). The analysis below records the preimplementation state and the decision that led to the gallery.

**Why Play currently looks old:** `Level5PreviewAccess` enters through the existing `Level5SealedDoor` prompt, but its `buildPreview()` calls only `Level 5 Architecture.Build(model, ORIGIN, {MapOnly=true})`. The ten reference modules are local, uninstalled drafts and are never required there. The door therefore builds the old static map at X=31,000; the playable round at X=17,000 is separate. This analysis uses the repository mirror and the last verified Studio manifest; implementation must start with a fresh live Studio Source/editor and instance check.

| Approach | What a DEV sees | Main blockers |
| --- | --- | --- |
| **A. Replace old scenery inside the static preview** | A single walk-through of the eventual eight-zone route with revised reference sections in place. Best final integration QA. | Current static architecture is 27,472 descendants. The audit's ten drafts were about 8,256 more: an overlay would be about 35,728 before preview helpers, above the 30,000 cap. The measured 8,929 removable old descendants are *candidates* whose removal must be paired with replacement; route floors, seven gates, clues, Watcher glass and F's pit/stairs cannot be deleted. Ten visual views also need mapped anchors within eight gameplay zones. Architecture's `K` construction kit is local to `Build`, so the drafts cannot just be required from `Level5PreviewAccess` without a compatible adapter or a scoped Architecture extension. Current standalone compositions also have mismatched footprint/orientation and several noncolliding floors. |
| **B. Separate reference gallery behind the same door** | A labelled **Level 5 reference work in progress** hub with ten distinct section cells, a camera viewpoint/pad for each, and return to lobby. It shows the new work in Play without pretending that it is the playable round. | The gallery needs a compatible `K` adapter, measured nonoverlapping placements and safe collidable camera/arrival pads; Facades' pieces, including its scenic ground, are noncolliding. Section 5's proposed camera is outside its lawn. Prompt travel between cells must stream and revalidate living DEV, range, round state and destination floor. Gallery cells must not overlap the playable X=17,000 world or the old preview X=31,000. The existing non-DEV ejection uses one cached model bounding box, so either keep cells in a compact remote cluster and build them all before `PreviewReady`, or test per-cell bounds. |

**Recommended interim path: B.** Keep the server-owned `Level5DeveloperPreviewPrompt` on the same sealed door and retain its `DevAccess.IsAllowed`, proximity, living, `InRound`/reserved-server, streaming, return-prompt and non-DEV ejection checks. In the preview-only build path, construct a separate, version-tagged gallery model instead of the old `Architecture.Build` map for this QA mode. Use a distinct remote origin such as X=47,000, beyond both the playable X=17,000 and current static preview X=31,000; place ten cells at footprint-based separated coordinates around it. Add a guarded hub floor and one collidable viewpoint pad per section. Use each draft's recorded camera position, with explicit section labels and `FidelityStatus="unverified-draft"`. Entry and cell-switch prompts must be server checked; do not rely on hiding UI. Build all cells atomically, count the completed preview model plus pads/prompts against 30,000, mark `PreviewReady` last, and destroy only the gallery model if assembly fails. A gallery of roughly 8.3k draft instances leaves ample room *within this per-preview cap*; recount the current source before implementation. Keep public Level 5 flags false and do not touch the playable Architecture path.

The current `getPreview()` will reuse any model with the old three ready attributes, so add an owner/content-version check: an old static preview must not silently satisfy a new gallery request in the same Play session. Preserve the return floor, marker and prompt contracts already tested. If the old static map also needs inspection, offer it later as a separately named DEV-only mode; loading both maps into one preview model would repeat the cap problem and a giant combined bounding box would complicate ejection.

**Longer-term path: A.** Replace scenery zone by zone after visual matching, using the measured removal ledger and preserving the actual gameplay route. Recount after every district; keep the seven-gate, clue and Watcher contracts. Once that integrated static preview is independently valid, the gallery can be retired. Neither option makes the current drafts 1:1 or live on Roblox by itself. The local drafts and any preview change must first be reconciled against live Studio, tested in Play for DEV/non-DEV access and return, exported to the repo with native data backed up, and committed. No publication is proposed while visual QA remains failing.
